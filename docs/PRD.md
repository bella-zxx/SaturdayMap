# 周六地图 MVP 产品需求文档

**版本：** v1.0  
**状态：** 已冻结

## 1. MVP 目标

用户粘贴一篇小红书分享链接后，系统自动获取帖子内容、提取其中的一个或多个地点、匹配真实 POI，并在用户确认后保存到个人地图。

## 2. P0 功能

| 编号 | 功能 | 要求 |
|---|---|---|
| F01 | 链接导入 | 用户粘贴小红书分享链接；不要求复制正文或上传截图。 |
| F02 | 内容获取 | 自动读取足够用于地点提取的帖子内容。 |
| F03 | AI 地点提取 | 识别一个或多个地点，提取地点特点及原帖中的推荐理由；每个地点保留 `source_url`。 |
| F04 | POI 匹配 | 为提取的地点匹配真实地点、地址和坐标。 |
| F05 | 用户确认 | 用户选择需要收藏的地点。 |
| F06 | 地图打标 | 将确认的地点显示在个人地图上。 |
| F07 | 地点详情 | 展示地点特点、推荐理由和来源信息；保存原始小红书链接。 |
| F08 | 基础搜索 | 搜索已经收藏的地点。 |

### 来源保存规则

- 原始小红书链接必须保存，属于 P0。
- 地点详情必须展示来源信息，属于 P0。
- `recommendation` 必须来自原帖，不得由 AI 随意编造。

示例数据：

```json
{
  "place_name": "武康大楼",
  "city": "上海",
  "recommendation": "适合拍照和 City Walk",
  "source_url": "https://www.xiaohongshu.com/explore/xxxx"
}
```

## 3. P1 功能

- 点击来源跳转至对应原帖。
- 同一地点关联多个来源：地图上保留一个地点，每篇来源分别保留链接和推荐理由。

## 4. 不纳入 MVP

- AI 行程规划
- 智能推荐
- 社交功能
- 路线规划
- 多人协作

## 5. 技术验证前置条件

MVP 开发前必须验证：仅凭用户提供的小红书链接，能否稳定获得足够的正文和图片信息用于地点提取。该验证尚未完成，不能认定任何候选解析方案已经通过。
