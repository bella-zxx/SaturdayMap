# 小红书链接解析可行性实验

## 目标

验证用户仅粘贴小红书链接时，系统能否稳定获得足够的帖子信息，用于后续 AI 地点提取。

## 通过标准

| 验证项 | 标准 |
|---|---|
| 链接解析 | 可识别分享短链并获得最终笔记地址 |
| 正文获取 | 可获得足够用于地点提取的正文 |
| 图片获取 | 可获得可供后续处理的图片地址或内容 |
| 多地点支持 | 输入内容保留帖子中主要地点的信息来源 |
| 用户操作 | 用户只需粘贴链接 |
| 稳定性 | 同一链接多次运行结果可靠，并记录失败原因 |

## 当前已知结果

- 分享短链可以展开到笔记地址。
- 直接网页获取尚未证明可以稳定取得完整正文和图片。
- 公开搜索索引尚未证明可以可靠获取内容。
- SocialDataX / Apify、TikHub、Rnote、xiaohongshu-mcp、RedNote-MCP 尚未完成端到端验证。

因此目前不能认定任何候选方案已经通过。

首个真实样本的重复测试记录见 [RESULTS.md](RESULTS.md)。

## 基线探针

`probe.py` 使用 Python 标准库：

1. 跟随重定向并记录最终 URL；
2. 记录状态码、响应类型、页面大小和标题；
3. 检查页面中是否出现常见正文、图片和嵌入数据线索；
4. 将 JSON 结果写到指定目录，便于重复测试和比较。

运行：

```bash
python3 probe.py --out results URL [URL ...]
```

该探针只验证公开网页基线，不绕过登录、验证码或平台访问控制。
